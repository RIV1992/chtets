# Following a change through a text

All material below is synthetic. These are teaching examples, not unseen evaluation evidence or claims about real standards.

## A corrected denominator

The original pilot summary says 18 of 24 participants reported easier onboarding. A correction changes the participant count to 36; the 18 reports are unchanged.

| Location | Basis or dependency | Required repair |
| --- | --- | --- |
| Results paragraph | Supplied count: 18 of 36 | Replace 24 with 36 |
| Results table | 18 / 36 = 0.5 | Replace 75% with 50% |
| Interpretation | A majority means more than half | Replace “a majority” with “half” |
| Headline and summary | Repeat the affected result | Update their quantity and scope |
| Method note | Self-report in one pilot | Preserve this limitation |
| Budget paragraph | Independent supplied cost | Leave it unchanged |

Usable result: “Half of the 36 pilot participants reported easier onboarding.” This does not establish that the intervention caused an improvement or that the result generalizes.

## A report using standards

Use a compact working table when a report needs an audit trail:

| Local ID and location | Requirement or claim | Exact basis | Applicability and state | Dependents |
| --- | --- | --- | --- | --- |
| R1, requirements section | Test T required under condition X | Supplied standard S, edition Y, clause 4.2 and its note | Project condition X unresolved; exception must be checked | C1, table 3 |
| E1, test section | T is planned | Supplied project schedule | Planned; no completed result | C1 |
| C1, conclusion | Compliance cannot yet be established from this material | R1 and E1 | Applicability and test evidence remain open | Executive summary |

Do not fill in a plausible standard number, clause, edition, or test result. If the task requires current status, verify it from accessible primary material. A requirement describes what must hold; it does not prove that this project meets it.

When the applicable edition or project condition changes, revisit R1, C1, table 3, and the executive summary. Keep the source statement, project fact, and inferred conclusion distinguishable. Include the table in the deliverable only when requested or useful for the audit.
